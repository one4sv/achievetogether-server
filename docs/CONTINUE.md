## Требования
1. В меню совместной привычки сверху владелец с аватаркой и подписью, ниже второй участник либо беседа. Класс active только у текущего пользователя/соответствующей ему беседы. Загрузка участников скелетоном.
2. Постоянный список добавления заменить кнопкой «Добавить участников» и модалкой. Для одиночной привычки приглашение, для пары создание/выбор беседы. В привязанной беседе кнопку не показывать; участнику, который не владелец, показать себя и роль в беседе.
3. Кто выполняет и комментирует: radioGroup «Только владелец / Все / Те, у кого есть права» (последнее для беседы). Проверять на сервере, а не только в интерфейсе.
4. Настройки совместки: первая группа отвечает за общий/личный прогресс всех типов выполнения: отметка, таймер, счётчик, задачи. Вторая только за блоки расписания. Участникам настройки доступны как структурированный текст вместо редактируемых radioGroup. Сохранить обязательное/необязательное участие в чате.
5. Принятый участник должен видеть статистику, выполнять и комментировать согласно правам независимо от публичной видимости привычки владельца. Реальный пример: testuser1 принял test от one4sv, привычка 19. Не менять их данные ради автоматических тестов.
6. Общие комментарии за день в dayCommentDiv: аватарки, имена авторов, переносы длинного текста, правильная мобильная структура и композер. Изменение комментариев атомарно по автору/дню; realtime обновление.
7. Свайп вправо закрывает меню активности без конфликта с другими горизонтальными жестами.
8. Удаление второго участника/из беседы и отвязка беседы только после подтверждения в модалке.
9. Посторонний с правом просмотра вместо настроек совместки видит ссылку «аватарка, имя, Владелец + 1» или «+ беседа» на аккаунт владельца.
10. Права редактирования данных и блоков, приглашения, выполнения, комментариев согласовать с правами ролей беседы. Заблокированный участник не получает доступ через альтернативные API.

## Проверки и известные недоработки
До потери среды локальные tsc+vite, проверки синтаксиса сервера, компонентные проверки меню/свайпа/переполнения и SQL-тесты с rollback проходили. Последняя повторная сборка не подтверждена. Полный API end-to-end не завершён из-за ограничений транспорта тестовой среды. Продакшен новых изменений не проверен.

Обязательно проверить/доделать:
- /calendar сейчас выбирает собственные привычки: приглашённые могут отсутствовать или отображаться Unknown habit.
- Блокировки беседы: habit_permissions.is_member и списки могут считать заблокированного участником; защита нужна во всех маршрутах.
- Участник пары с can_invite: модалка создания/привязки беседы не должна обещать недоступное владельческое действие.
- Стили CreateChatInfo внутри новой модалки, safe-area, длинные комментарии, клавиатура iPhone, can_comment=true при can_complete=false.
- Полный цикл личная привычка → приглашение → принятие → беседа → роли → удаление/отвязка. Приватность приглашений не обходить.
- Делегированное edit_info разрешает только предусмотренные поля, не все настройки владельца.
- Общий/личный прогресс таймера, счётчика, задач и обычных отметок.
